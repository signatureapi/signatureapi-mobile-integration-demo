# Demo server

The backend the mobile apps call. It holds the SignatureAPI key, creates a one-page sample envelope, and returns the signer's ceremony URL. The apps never talk to SignatureAPI directly.

TypeScript on Node.js, with Express 5 and zod.

## Setup

Requires Node.js 22.18 or later (it runs TypeScript natively).

```bash
npm install
npx --yes signatureapi init   # approve in the browser; writes SIGNATUREAPI_KEY to .env without printing it
npm run dev                   # restarts on file changes
```

Or copy `.env.example` to `.env` and set:

| Variable | Default | |
|---|---|---|
| `SIGNATUREAPI_KEY` | none | A **test** key (`key_test_…`). The server refuses to start with anything else. |
| `PORT` | `3000` | Listens on all interfaces, so a phone on the same network can reach it. |
| `SIGNATUREAPI_BASE_URL` | `https://api.signatureapi.com/v1` | |

For production-style runs, build first: `npm run build && npm start`.

## API

| Method and path | Does |
|---|---|
| `POST /ceremonies` | Creates the sample envelope and returns `{ envelopeId, recipientId, ceremonyUrl, embedOrigin }`. Waits until SignatureAPI has processed the envelope. |
| `GET /envelopes/:envelopeId/ceremony-url` | Returns a URL for the signer's current ceremony, to resume after the app was closed. `409` when there is no active ceremony (for example, already signed). |
| `GET /envelopes/:envelopeId` | Envelope and recipient status, for confirming the outcome on the server side. |
| `POST /recipients/:recipientId/ceremony` | Replaces the signer's ceremony with a new one. The previous URL stops working. |
| `GET /health` | `{ "ok": true }` |

`POST /ceremonies` accepts an optional JSON body. Everything has a default:

| Field | Default | |
|---|---|---|
| `name`, `email` | `Demo Signer`, `signer@example.com` | Synthetic signer. |
| `language` | `en` | `en`, `es`, `fr`, `it`, `pt`, `de`, `zh`, `hu` or `nl`. |
| `redirectDelay` | `0` | Seconds the ceremony shows its own result page before handing back to the app (0–20). |
| `embedOrigin` | `null` | An https origin allowed to frame the ceremony in an `<iframe>`. Leave it unset for a top-level WebView. |

`POST /recipients/:recipientId/ceremony` accepts `{ "embedOrigin": … }`.

Invalid input returns `400` with the failing fields. Errors from SignatureAPI return `502`, or `404` when the envelope or recipient does not exist.

## How it creates the ceremony

- **Custom authentication.** The app vouches for the signer, so SignatureAPI returns the ceremony URL instead of emailing it. The authentication data (a random session reference and a timestamp) lands in the audit log. A real integration would reference its own login session here.
- **No `redirect_url`.** Embedded ceremonies don't use it.
- **One uploaded PDF, reused.** `assets/sample.pdf` is uploaded once and reused for 20 hours. Uploads expire after 24.

The sample document is generated by `npm run make-pdf` from the text and place positions in [`src/sample-document.ts`](src/sample-document.ts), so the printed labels and the signature place stay aligned.

## Security notes

- Ceremony URLs are bearer credentials: anyone holding one can sign. The server returns them to the app but never logs them.
- This demo has no user authentication. A real backend must check that the caller is the signer before returning or replacing a ceremony URL.
- A live key is rejected at startup, and the error message never echoes the key.

## Tests

```bash
npm test         # end-to-end against SignatureAPI test mode; needs the key in .env
npm run typecheck
```

The end-to-end suite starts the real server and checks that:

- a ceremony URL is issued;
- the ceremony refuses framing without `embedOrigin` and allows exactly the requested origin with it;
- resuming returns a working URL;
- replacing issues a new one;
- bad input is rejected before any SignatureAPI call;
- no ceremony URL appears in the server's output.

Without a key the suite is skipped, with a message saying so.

## Layout

```
src/
  index.ts              Entry point: config, wiring, listen
  config.ts             Environment validation (test keys only)
  http/app.ts           Routes and error mapping
  http/schemas.ts       Request validation
  ceremonies.ts         Envelope and ceremony logic
  sample-document.ts    Sample PDF places and printed text
  signatureapi/         Typed SignatureAPI client and resource types
scripts/make-sample-pdf.ts
test/                   End-to-end suite and the live-key check
```
